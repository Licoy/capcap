# Code-signing certificate

This directory holds the self-signed certificate used to sign **every** capcap
build — local (`scripts/bundle.sh`) and CI (`.github/workflows/release.yml`).
Signing with one stable identity keeps the app's macOS TCC permission grants
(Screen Recording / Accessibility) intact across rebuilds and updates.

This fork (Licoy/capcap) ships with Bundle ID
`com.github.licoy.capcap.desktop` and publishes releases from
`https://github.com/Licoy/capcap`.

## Files (git-ignored — never committed)

- `capcap-signing.p12` — the certificate + private key. **Back this up.**
- `capcap-signing.p12.base64` — base64 of the `.p12`, for the GitHub secret.

Default `.p12` password: `capcap` (set when generated by
`scripts/generate-signing-cert.sh`).

## First-time setup (operator)

1. Generate a cert once:

   ```sh
   scripts/generate-signing-cert.sh
   # or write into this directory:
   scripts/generate-signing-cert.sh scripts/signing
   ```

2. Import on a local machine so `codesign` can use the identity:

   ```sh
   security import scripts/signing/capcap-signing.p12 \
     -k ~/Library/Keychains/login.keychain-db -P capcap -T /usr/bin/codesign
   ```

3. Configure GitHub Actions secrets (repo Settings → Secrets → Actions):

   | Secret | Value |
   |--------|-------|
   | `MACOS_CERTIFICATE` | Contents of `capcap-signing.p12.base64` |
   | `MACOS_CERTIFICATE_PWD` | The `.p12` password (`capcap` by default) |
   | `MACOS_SIGNING_IDENTITY` | `CapCapRelease` |
   | `KEYCHAIN_PASSWORD` | Any throwaway string |

4. Release with:

   ```sh
   ./bump.sh -v 1.0.1 -p
   ```

   That updates both app and share-extension Info.plist versions, commits,
   tags `vX.Y.Z`, and pushes — the `v*` tag triggers the Release workflow.

## Important

Losing this `.p12` (or regenerating it) gives the app a new identity, forcing
every user to re-authorize permissions once. Keep it backed up and reuse it.
Never commit the live `.p12` or its base64 into the repository.
